### 9. SSR 水合一致性全站收口（凌晨，用户报「报告页水合报错」）

用户报告报告页「已解锁 4/12」水合报错（服务端回退演示集 4 枚 vs 浏览器本地 3 枚）。修复后按超彻底标准做全站审计：工作流 6 扫描 + 4 对抗验证 agent，13 条确认发现全部修复。

- **根因模式**：渲染期直读 localStorage / 系统时钟。服务器与浏览器两端状态不同 → 首帧文字/属性不一致 → React 水合失败。共四类：① 本地存储进 useState 惰性初始化器（成就集、段位、提醒、标记、取消攻略进度、通知设置）；② useMemo 渲染期直读本地存储（顶栏铃铛的断点/预算覆盖/手动记账）；③ 渲染期取系统时钟（订阅卡倒计时按「今天」外推，部署后服务器 UTC 与用户 UTC+8 每天 8 小时日期差 1 天；铃铛通知 id 按本机日历日）；④ framer-motion useReducedMotion（服务端 null、客户端首帧同步读 matchMedia 得布尔，`!` 取反两端 initial 不一致）。
- **修复口径（统一挂载门控）**：新增共享 hook `src/lib/use-mounted.ts`（useSyncExternalStore 服务器快照 false，挂载后 true 重渲染）；成就集/段位沿用订阅式读取（`useUnlockedIds`/`useRankTier`，带服务器快照缓存）；订阅卡提醒/标记/取消攻略进度/倒计时、顶栏铃铛全量派生（含断点/预算/手动记账读取与 Date.now 派生）、洞察页收藏、成就墙减动判定全部改 mounted 门控——挂载前两端同口径渲染空态/占位，挂载后读真实值；倒计时首帧渲染「扣费日计算中」占位；成就墙挂载前不输出 initial 内联样式（锁→解锁重挂载动画发生在挂载后不受影响）。coming-soon-modal 同步改用共享 hook。

### 10. 「conditional use of use」控制台警告定界（午后，用户报 DevTools Console Error）

用户报告开发模式下控制台出现 `This library called use() to suspend in a previous render but did not call use() when it finished`（Next.js 16.4.0 / Turbopack）。结论：**开发模式专属警告、来自 Next.js App Router 内部、无害，无需改代码**。

- **源码级定界**：项目源码零处直接 `use()` 调用；依赖排查（framer-motion 14.1.0、react-query 5.104.2、zustand、echarts）均无 `use()`；栈内唯一挂起点是 Next.js `ClientPageRoot`（client-page.js）的 `use(SearchParamsContext)`——Next 把搜索参数 Promise 放进 SearchParamsContext 挂起组件，若重试渲染时该 context 值已不再是 thenable（Promise 被替换为普通对象或 serverProvidedParams 翻转的竞态），React 开发构建在 finishRenderingHooks 检出「挂起过但这次没再 use()」并报出该警告（react-dom-client.development.js 约 L8066-8072；生产 bundle 无此代码，grep 确认 0 命中）。我方 useSearchParams 走 useContext（navigation.js），自身从不调 use()，useSearchParams 页面均按要求包 Suspense 边界（insights/upload/login/register）。
- **复现尝试全部零命中**：6 组 Playwright 脚本（12 页整页加载、8 组交互含视图切换/弹层/Toast/收藏/登录、体检全动线、快速导航往返、中断式竞态：挂起期间切走/切回）在 dev server 上监听 console/pageerror，命中 0 条——确认属偶发竞态，无稳定触发路径。
- **处置**：npm 最新稳定版即 16.4.0（无补丁可升，canary 升级风险大于收益）；警告不影响渲染与功能、生产构建不输出，标记为已知无害告警。Web 佐证：React dispatcher 相关修复 commits（a8f971b7、09f46e4、9f66192）、Next.js PR #94436（16.3.0-canary.40 服务端 abort 场景）均为框架内部此类竞态的持续收窄。
